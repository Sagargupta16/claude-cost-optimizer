# Pricing Data Reference

> Split out of [`CLAUDE.md`](../CLAUDE.md) because CLAUDE.md loads in full at the start of
> every session, so every line in it is paid for in every session whether the task needs it or
> not, and a shorter file is followed more reliably. Anthropic's guidance is to "target under
> 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence"
> ([memory docs](https://code.claude.com/docs/en/memory); see also
> [guide 02](../guides/02-context-optimization.md)). The detail below is only needed when a task
> touches pricing, so it lives here and is read on demand.

> against it. Read it whenever a task touches rates, model IDs, context windows, cache

## Pricing Data

Current Claude API pricing (verified 2026-10-09):

- **Fable 5.1** (most capable widely released model, `claude-fable-5-1`; Anthropic points it at demanding reasoning and long-horizon work): **$10/$50 per 1M input/output** -- same posted rate as Fable 5, 2.5x Opus 5.5's. 1M context at standard rates (1M is both default and max). 128K max output. **Cache hit $0.25 -- 0.025x base input, the deepest cache discount in the lineup** (a quarter of Fable 5's $1; Opus 5.5 reads at 0.05x, every other model at 0.1x). 5m-write $12.50, 1h-write $20. Batch $5/$25. Min cacheable prompt **512**. Because a hit is so cheap relative to a miss, a `max_tokens: 0` keep-alive on the 5-minute TTL usually beats paying the 2x 1-hour write. Adaptive thinking **always on** (`thinking: {type: "disabled"}` and `budget_tokens` both return 400; control depth with `effort`, which supports `low` through `xhigh` and `max`). **Three breaking changes vs Fable 5**: forced tool use (`tool_choice` `any`/`tool`) returns 400; thinking blocks are bound to the producing model (other models drop them, unbilled); and editing earlier turns invalidates thinking blocks ("preserved thinking" -- accounts created on/after 2026-08-31 get a 400 on edited history, so keep harnesses append-only). Adds per-message `effort` (beta `mid-conversation-output-config-2026-07-01`), turn-scoped `clear_at: "next_user_message"` system messages (beta), `thinking.display: "updates"` progress notes (beta), and content provenance. **No Fast Mode. Released 2026-09-01.

The "cache hits are 90% off" shorthand is wrong on those four models. Never derive a cache rate by multiplying input by 0.1; read the per-model rate. **The list above is necessary but not sufficient, and it has failed twice.** v1.11.0 and v1.12.0 both shipped with the checklist followed only partway. Two automated checks now catch the failure modes it misses, and CI runs both on every pull request:

```bash
python scripts/check-pricing-sync.py .   # verified-date drift, stale "retires <past date>", relative countdowns, doc freshness
python scripts/check-links.py .          # broken relative links and heading anchors
```

The canonical verified date is the `_PRICING_VERIFIED_DATE` constant in `tools/claude-rate/rate.py`. Bump it there first; the checker then reports every file still carrying the old stamp, which is faster and more reliable than working down the list by hand.
